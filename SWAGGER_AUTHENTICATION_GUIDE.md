# Swagger Authentication Guide for Requirements Management API\n\nThis guide explains how to authenticate with the Swagger UI interface for the Requirements Management API using the same credentials as the backend.LoadTests.\n\n## Authentication Overview\n\nThe system uses two different authentication flows:\n\n1. **Client Credentials Flow** - Used by backend.LoadTests and backend.ApiTests\n   - Client ID: `rqmtmgmt-backend`\n   - Client Secret: `backend-secret`\n   - Scope: `rqmtmgmt.api`\n\n2. **Authorization Code Flow with PKCE** - Used by Swagger UI\n   - Client ID: `swagger-ui`\n   - No client secret (public client)\n   - Scopes: `openid`, `profile`, `rqmtmgmt.api`\n\n## Method 1: Direct API Access (Recommended for Testing)\n\nThis method uses the same credentials as your load tests to get a JWT token directly.\n\n### Using the Shell Script\n\n```bash\n# Run the authentication test script\ncd /home/wtruitt/src/repos/RqmtMgmt\n./test-api-auth.sh\n```\n\n### Manual Steps with curl\n\n1. **Get Access Token:**\n```bash\nTOKEN=$(curl -k -s -X POST \"https://rqmtmgmt.local/connect/token\" \\\n  -H \"Content-Type: application/x-www-form-urlencoded\" \\\n  -H \"Accept: application/json\" \\\n  -d \"grant_type=client_credentials&client_id=rqmtmgmt-backend&client_secret=backend-secret&scope=rqmtmgmt.api\" \\\n  | jq -r '.access_token')\n\necho \"Token obtained: ${TOKEN:0:20}...\"\n```\n\n2. **Make API Calls:**\n```bash\n# Test with Dashboard statistics endpoint\ncurl -k -s -H \"Authorization: Bearer $TOKEN\" \\\n  -H \"Accept: application/json\" \\\n  \"https://rqmtmgmt.local/api/Dashboard/statistics\" | jq .\n\n# Test with other endpoints\ncurl -k -s -H \"Authorization: Bearer $TOKEN\" \\\n  -H \"Accept: application/json\" \\\n  \"https://rqmtmgmt.local/api/Projects\" | jq .\n```\n\n### Available API Endpoints\n\nSome key endpoints you can test:\n- `GET /api/Dashboard/statistics` - Dashboard statistics\n- `GET /api/Projects` - List all projects\n- `GET /api/Requirement` - List requirements\n- `GET /api/TestSuite` - List test suites\n- `GET /api/TestCase` - List test cases\n- `GET /api/User` - List users\n\n## Method 2: Swagger UI Interactive Authentication\n\n**Important Note:** The Swagger UI uses a different OAuth2 flow that requires user interaction and would typically need a user account to log in. The client credentials from the load tests won't work directly in Swagger UI.\n\n### Steps to Use Swagger UI:\n\n1. **Navigate to Swagger:**\n   ```\n   https://rqmtmgmt.local/swagger/index.html\n   ```\n\n2. **Click the \"Authorize\" button** (green lock icon in the top right)\n\n3. **In the OAuth2 Authorization Modal:**\n   - Client ID: `swagger-ui` (pre-filled)\n   - Leave Client Secret empty (it's a public client)\n   - Select the scopes you need:\n     - ✅ `openid` - Required for OpenID Connect\n     - ✅ `profile` - User profile information\n     - ✅ `rqmtmgmt.api` - API access\n\n4. **Click \"Authorize\"** - This will redirect you to the IdentityServer login page\n\n5. **Login with User Credentials** - You'll need valid user credentials configured in the IdentityServer\n\n6. **After successful login**, you'll be redirected back to Swagger with an active session\n\n7. **Test API endpoints** by clicking \"Try it out\" on any endpoint\n\n## Method 3: Playwright Automation (For Development/Testing)\n\nI've created a Playwright script that can automate the Swagger authentication process:\n\n```bash\n# Install dependencies\nnpm install\nnpx playwright install chromium\n\n# Run the automation script\nnode swagger-auth-test.js\n```\n\nThe script includes:\n- Direct token retrieval using client credentials\n- Automated API testing\n- Interactive Swagger UI automation\n\n## Troubleshooting\n\n### Common Issues:\n\n1. **SSL Certificate Errors:**\n   - Use `-k` flag with curl to ignore SSL certificate issues\n   - For browsers, you may need to accept the self-signed certificate\n\n2. **Token Expiration:**\n   - Tokens expire after 1 hour (3600 seconds)\n   - Get a new token when needed\n\n3. **CORS Issues:**\n   - The API is configured to allow requests from the Swagger UI origin\n   - If testing from other origins, you may encounter CORS restrictions\n\n4. **Authentication Failures:**\n   - Verify the IdentityServer is running at `https://rqmtmgmt.local`\n   - Check that the client credentials are correct\n   - Ensure the API backend is running and accessible\n\n### Debugging Authentication:\n\n1. **Check IdentityServer Discovery:**\n   ```bash\n   curl -k \"https://rqmtmgmt.local/.well-known/openid_configuration\" | jq .\n   ```\n\n2. **Verify Token Contents:**\n   ```bash\n   # Decode JWT token (replace YOUR_TOKEN with actual token)\n   echo \"YOUR_TOKEN\" | cut -d. -f2 | base64 -d | jq .\n   ```\n\n3. **Test API Health:**\n   ```bash\n   curl -k \"https://rqmtmgmt.local/health\"\n   ```\n\n## Configuration Details\n\nThe authentication system is configured as follows:\n\n- **IdentityServer URL:** `https://rqmtmgmt.local`\n- **Token Endpoint:** `https://rqmtmgmt.local/connect/token`\n- **Authorization Endpoint:** `https://rqmtmgmt.local/connect/authorize`\n- **API Base URL:** `https://rqmtmgmt.local/api`\n\n### Client Configurations:\n\n1. **Backend Client (for load tests):**\n   - Client ID: `rqmtmgmt-backend`\n   - Client Secret: `backend-secret`\n   - Grant Type: `client_credentials`\n   - Scopes: `rqmtmgmt.api`\n\n2. **Swagger UI Client:**\n   - Client ID: `swagger-ui`\n   - Grant Type: `authorization_code` with PKCE\n   - Scopes: `openid`, `profile`, `rqmtmgmt.api`\n   - Redirect URI: `https://rqmtmgmt.local/swagger/oauth2-redirect.html`\n\n## Example API Response\n\nWhen successfully authenticated, you should see responses like:\n\n```json\n{\n  \"requirements\": {\n    \"total\": 479,\n    \"approved\": 44,\n    \"draft\": 434,\n    \"implemented\": 1,\n    \"verified\": 0\n  },\n  \"testSuites\": {\n    \"total\": 136,\n    \"active\": 136,\n    \"completed\": 0\n  },\n  \"testCases\": {\n    \"total\": 249,\n    \"passed\": 0,\n    \"failed\": 0,\n    \"notRun\": 249\n  },\n  \"testPlans\": {\n    \"total\": 70,\n    \"executionProgress\": 0,\n    \"coveragePercentage\": 0\n  }\n}\n```\n\nThis confirms that your authentication is working and you have access to the API data.\n
